# Brief2Ship AI

**AI Brief-to-Submission Copilot** — Turn any hackathon brief into a submit-ready MVP plan.

> Stop guessing what to build. Paste any hackathon or assignment brief and get a clear MVP scope, sprint plan, risk score, and submission kit before your deadline kills the project.

**🔗 Live app: [brief2ship-ai.vercel.app](https://brief2ship-ai.vercel.app)**

Built for **Vibe2Ship**, a national-level solo online vibe-coding hackathon by **Coding Ninjas 10X Club** in collaboration with **Google for Developers**.

---

## The Problem

Most builders don't lose hackathons because they can't code. They lose because they:

- misunderstand the brief
- overbuild the wrong features
- miss required submission items
- waste time on low-impact work
- fail to pitch clearly
- submit incomplete README / demo links

By the time they realize, the deadline has already killed the project.

## The Solution

Brief2Ship AI is a **meta-hackathon tool**: it reads any brief and instantly returns a complete, ruthlessly practical execution plan so you spend your last hours shipping instead of guessing.

For one pasted brief it generates:

- **MVP scope** — must-build, nice-to-have, and a cut list with reasons
- **Judge Lens** — what judges actually score and how to satisfy each criterion
- **Submission risk score** and critical risks
- **Recovery sprint plans** — 2-hour, 6-hour, and 12-hour action plans
- **Task board** — kanban with priorities you can move across Todo / Doing / Done
- **Submission kit** — README draft, 60-second pitch, demo script, and checklist (all copyable)
- **Readiness score** out of 100 with a final verdict and what to fix first

## Gemini Usage

The core analysis is generated by the **Gemini API** through **Google AI Studio** (`gemini-1.5-flash`).

- The API route `POST /api/analyze` sends the brief to Gemini with a senior-hackathon-judge system prompt and `responseMimeType: application/json` for strict JSON output.
- The response is parsed and **normalized** so a partial or malformed reply never crashes the UI.
- If `GEMINI_API_KEY` is missing or the API call fails, the app transparently falls back to a **high-quality mock response** tuned to the Vibe2Ship brief — so the demo always works. The UI shows a badge indicating whether the result came from Gemini or the mock fallback.

## Setup

```bash
# 1. Install dependencies
npm install

# 2. (Optional) Add your Gemini key — the app works without it via mock fallback
cp .env.example .env.local
# then edit .env.local and set GEMINI_API_KEY=...

# 3. Run
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

### Environment Variable

| Variable         | Required | Description                                                                 |
| ---------------- | -------- | --------------------------------------------------------------------------- |
| `GEMINI_API_KEY` | No       | Google AI Studio / Gemini API key. Without it, the app uses a mock fallback. |

Get a free key at [aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey).

## Demo Flow (60 seconds)

1. Click **Use Vibe2Ship Sample Brief** (or paste your own)
2. Click **Analyze Brief**
3. Show the **submission risk score**
4. Show the **MVP scope** and **cut list**
5. Show the **recovery sprint plan**
6. Show the generated **README + pitch**
7. Show the **readiness score** and verdict

The whole flow makes the value obvious in under a minute.

## Deploy to Vercel

1. Push this repo to GitHub.
2. Import it into [Vercel](https://vercel.com/new).
3. (Optional) Add `GEMINI_API_KEY` in **Project → Settings → Environment Variables**.
4. Deploy. No database, no auth, no extra setup.
